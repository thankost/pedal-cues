# PedalCues: notes for Claude

JUCE plugin (VST3 / AU on macOS / LV2 on Linux / Standalone; Windows, macOS (universal: Intel from 10.13, Apple Silicon from 11; `CMAKE_OSX_DEPLOYMENT_TARGET` 10.13 and the pkg's `os-version min`) and Linux; tested in Reaper, DAW-neutral wording elsewhere) that turns MIDI changes for the Quad Cortex / QC Mini / Nano Cortex, Kemper, Fractal, Line 6, HeadRush, Darkglass, Boss, Strymon, Meris, Chase Bliss, Walrus, Source Audio, EHX, Eventide and Whammy V / DT, and tiles for any other MIDI device (custom MIDI devices, beta), into drag-and-drop tiles. The website headline lists the brands, ending "& more amp modellers, effects & pedals, or any MIDI device" (`docs/index.html` h1, title and meta descriptions), and so does the README intro: update both when a brand is added (the GitHub About text is the author's; don't change it). Every site page resets the scroll to the top on reload (`history.scrollRestoration = 'manual'`, kept in `Tools/make_site_pages.py` for the generated pages). The author is Thanasis Kostopoulos (GitHub `thankost`). The repo is public: https://github.com/thankost/pedal-cues. The download site is https://thankost.github.io/pedal-cues/, served from `docs/` on `main`.

## Build and test

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DPEDALCUES_BUILD_DOCS=ON   # once
cmake --build build                                                       # also installs VST3/AU to ~/Library/Audio/Plug-Ins
build/PedalCuesTests_artefacts/Release/PedalCuesTests                     # unit tests, must print "All tests passed"
build/PedalCuesTests_artefacts/Release/PedalCuesTests --online            # optional: real GitHub update check
build/DocShots_artefacts/Release/DocShots docs/images                     # regenerate every screenshot and diagram
```

- The shell is zsh. Unquoted `$var` does not word-split and `%G?` needs quoting, so use arrays or `bash -c` for loops.
- DocShots renders the real UI components with demo data. Update checks are answered offline there, so the header shows "Up to date".
- To check a dialog (AlertWindow) visually, temporarily add a snapshot of the modal component to DocShots, render it to the scratchpad, then restore the file.

## Releases

Use the `release` skill (`.claude/skills/release/SKILL.md`). In short:
1. Bump `project(PedalCues VERSION x.y.z)` in `CMakeLists.txt`.
2. Add the version at the top of `CHANGELOG.md`, in plain words for musicians, then run `python3 Tools/make_site_pages.py` to rebuild `docs/changelog.html` and `docs/guide.html` (never edit those pages by hand).
3. Build and run the tests.
4. Commit with a message that works as release notes: the first line is `vX.Y.Z: summary`, then `- bullet` lines. CI copies the tagged commit's message into the GitHub release, and the plugin's update window shows it under "What's new".
5. Push `main`, then tag `vX.Y.Z` and push the tag. CI (`.github/workflows/build.yml`) builds the zips and the macOS installer (`Tools/make_macos_pkg.sh`: app to /Applications, VST3/AU to /Library/Audio/Plug-Ins, non-relocatable bundles, a welcome page saying to quit the DAW, `must-close` for the app's bundle id `com.athkost.pedalcues` so Installer asks to quit a running PedalCues, not Developer-ID signed) and publishes the release. Windows: an Inno Setup installer (`Tools/windows-installer.iss`, built in CI with ISCC: app to Program Files\PedalCues, VST3 to Common Files\VST3, a fixed AppId so a newer one replaces the old, Restart Manager asks to close PedalCues or a DAW that has the plugin loaded, not code-signed so SmartScreen asks once). Linux: the zip has `install.sh` (`Tools/linux-install.sh`: VST3 to ~/.vst3, LV2 to ~/.lv2, app to ~/.local/bin + a .desktop entry, replaces the old copy, `--uninstall`). The app's Update button downloads the pkg on macOS, the Setup.exe on Windows and the zip on Linux. The website's download links point at `releases/latest/download/...`, so link a new asset only after the release that has it is published.
6. Wait for one release to finish before tagging the next. CI marks only the highest version as Latest.
7. Confirm the release has `PedalCues-macOS.pkg`, `PedalCues-Windows-Setup.exe`, `PedalCues-macOS.zip`, `PedalCues-Windows.zip` and `PedalCues-Linux.zip`, is Latest, and the commit shows as verified.
8. Linux: CI builds on Ubuntu 22.04 (needs libudev-dev for hidapi). Nobody has tested it on real Linux hardware yet; USB sync there needs the udev rule from the guide.

## Domain facts (verified on real gear, by the user, or from the manufacturer's manual)

- **Quad Cortex MIDI:** bank CC#0, setlist CC#32 (value = the setlist number the QC shows; **0 = Factory Presets**, per Neural DSP's docs and a user's report; sent as setlist − 1 before v0.4.28, which was off by one), then Program Change; scenes CC#43 (0-7); footswitches CC#35-42 (0 off / 127 on); tap tempo CC#44 (any value, one press; manual); tuner CC#45; **Gig View screen CC#46** (0 close / 127 open, per the QC manual; Utilities' Gig View On/Off tiles); **footswitch mode CC#47: 0 = preset, 1 = stomp, 2 = scene**. The QC manual order is wrong on the author's unit, so keep this mapping.
- **QC Mini** (`ampUnit` 5, `state::qcMiniAmpUnit`, not beta: the Mini manual lists the same MIDI as the QC; from Neural DSP's Mini manual): the Quad Cortex page and `QC` data with Mini labels. 4 footswitches on two pages: CC#35-38 = A-D Page I, CC#39-42 = A-D Page II (= the QC's E-H); CC#43 0-3 Page I, 4-7 Page II (`qc::miniLabel` "A (I)"); CC#64 = footswitch page (0-63 I / 64-127 II, Mini only, Page I / Page II utilities). Same CC#0/32/44/45/46/47, one EXP jack (Exp 2 MIDI only). MIDI In and Out / Thru are 3.5 mm TRS Type A (`AmpInfo::midiIn` "TRS MIDI In"); the manual doesn't say whether USB MIDI reaches the Thru (`usbToThru` 3). Sync from QC hints at the right unit when it finds a Mini (`QcUsb isMini`).
- Both QC manuals (4.1.1) say CC#47 picks a **mode slot** (0 = slot 1 Preset, 1 = slot 2 Scene, 2 = slot 3 Stomp by default, reorderable); the author's QC answers 1 = Stomp, 2 = Scene, so the tiles keep that.
- **Looper X** (QC and QC Mini manuals 4.1.1; Quad Cortex page > **Looper** view, `qcLooperView`, `cues::qc::looper`): actions toggle with any value 64-127 (Duplicate 49, One Shot 50, Half Speed 51, Punch 52, Record/Overdub 53, Play/Stop 54, Reverse 55, Undo/Redo 56; `Cue::toggles`), settings take values (CC#48 0-63 opens / 64-127 closes the screen, 57 Duplicate Free/Sync, 58 Quantize 0 off / 1-8 beats / 9 = 16, 59 Clock Start Free/Sync, 60 Perform/Parameters). Needs a Looper X block in the preset; not verified on the author's QC yet.
- CC#35-42 act like pressing the footswitch in the QC's *current* mode. In Scene mode, footswitch A selects scene A.
- **Known QC limitation:** MIDI Thru only forwards MIDI arriving at the 5-pin MIDI In, never MIDI received over USB.
- Working setups, always with two cue tracks (**QC Cues**, **Whammy Cues**) set to *Send to original channels*:
  1. **Daisy chain** (what the author uses): interface MIDI Out → QC MIDI In → QC Thru → Whammy. Both tracks send to the interface MIDI Out.
  2. **Separate MIDI cables:** MIDI Out 1 → QC, MIDI Out 2 → Whammy.
  3. **QC over USB + interface:** QC track → Quad Cortex (USB), Whammy track → interface MIDI Out.
  - Not working: QC on USB only, with the Whammy on the QC's Thru.
- **Whammy V / Whammy DT** (`whModel`: 0 = V, 1 = DT; since v0.8.8 two entries in the Effects & Pedals list ("Whammy V", "Whammy DT", both `fxUnit` 0, the entry's `templateId` "v"/"dt" sets `whModel`); the faceplate switch was removed, the faceplate only shows the name; part of *Your setup*). `pedalInfo` names it "Whammy V" / "Whammy DT", short name "Whammy". The tour's "Got a Whammy DT?" step shows DT > Drop Tune via `showWhammyDt` and restores the user's choice after.
- **How to connect's daisy chain** (`chainNote`, `AmpInfo::usbToThru`): the button says "MIDI cable in, not USB" unless the unit passes USB to its Thru (1); when it's picked, an amber note explains the unit's case (0 never, 2 only with `usbThruSetting`, 3 undocumented, 1 passes). The DAW steps use generic roles (amp modeller track / pedal track) with the current devices as "e.g." names. The DT's Whammy side uses the V's Classic numbers (PC 1-21 on / 22-42 bypassed); the DT has no Chords mode, and on the DT PC 43-78 are **Drop Tune** (DT manual p.13): Shift Up 1-7, Oct, Oct+Dry = 43-51 on / 61-69 bypassed; Shift Down 1-7, Oct, Oct+Dry = 60-52 on / 78-70 bypassed (`whammy::dropTuneProgram`). So Chords is hidden on the DT. The DT's Momentary footswitch has no MIDI message. CC#11 treadle is the same on both. Drop Tune view: `whDropTuneView`.
- **Kemper** (`Source/KemperPage.cpp`, `cues::kemper`; from Kemper's MIDI Parameter Documentation, not tested on real hardware). `ampUnit` (0 = Quad Cortex, 1 = Kemper Profiler, 2 = Kemper Player) picks what the first tab shows (`makeAmpPage`); the tab is named after the unit (`ampUnitName`), Kemper green, with a ▾ menu (`amp.unit`), also listed in the unit picker. Performance mode: slot index = (perf-1)*5+slot, sent as CC#32 bank LSB (index/128) + PC (index%128); the Player has no bank, PC only, 10 banks of 5. CC#50-54 = slot 1-5 of the current performance (**Load P1 first** off, `kemperSlotFirst`). Effect switches take **1/0** (not 127): A-D CC#17-20, X 22, MOD 24, DLY 26 cut / 27 tails, REV 28 / 29 (`kemperKeepTails`). Tuner 31, tap 30, rotary 33, morph button 80. Pedals view (`kemperPedalsView`): wah CC#1, pitch 4, volume 7, morph 11, sharing the QC expression shapes. The Kemper only reports the current rig name over SysEx and no colours, so there is no sync. The Kemper's global MIDI channel defaults to Omni. **USB MIDI has no MIDI Thru** on the Kemper (Kemper staff on their forum), the same as the QC; all Profilers (OS 10.2+) and the Player take MIDI over USB. The Whammy V / DT have only a 5-pin MIDI In, no USB MIDI. The wiring guide (`WiringGuide(ampUnit)`) follows the unit.
- **Custom MIDI devices (beta)** (`Source/CustomPage.cpp`, `cues::custom`, `state::createCustomUnit/addCustomUnit/saveUnit/loadUnit`): `ampUnit` 3 (`state::customAmpUnit`) shows the selected one (`selectedCustomUnit`) of `CustomUnits > Unit { name, colour, notes, programBase } > Group > CueTile { name, colour, note, messages }`. Internal IDs say "unit"; everything the user sees says **MIDI device** (files `.pedalcues-device`, root `PedalCuesUnit`). `messages` is text like `bank 1, PC 5, CC#34 = 2` (Program Change, Control Change, bank select = CC#0), all sent together at the drop point; the guided tile editor (`TileEditor`, rows per message, starting points Preset / Bank + preset / Switch on/off / Set a value) writes it via `custom::describe`, which `custom::parse` reads back. **No wait/delay step**: it isn't MIDI and the gap a device needs is unverified; users drop a preset tile, then a scene tile just after it. Wording is device-neutral (synths, loopers too); the QC, Kemper and Whammy pages keep their guitar terms. `ui::AmpInfo` / `ampInfo (state)` gives the unit's name, wiring-box name, short name and colour for the tab, the MIDI strip, How to connect and the wiring guide. A custom device has its own channel (`IDs::channel`); its Test sends its first valid tile. Custom devices are part of the setup (saveLibrary/loadLibrary) and the project. **Expression view** (`cuExpressionView`, `CustomExpression` in CustomPage.cpp): MovesPanel shapes, Set to tiles and Draw on the device's `expCc` (per unit, default 11 = MIDI standard Expression, exported with the device); `cuBeats/cuCurve/cuReset/cuDraw/cuDrawing/cuDrawingName` on the root, `cuReset` in the setup.
- **Search** (`Source/Fuzzy.h`, `ui::SearchBox`, `ui::layoutFilteredRows`): QC presets, Kemper performances and custom device tiles. Fuzzy on the name (letters in order, word starts and runs score higher, one typo for words of 4+ letters); the location / messages / note only as plain text, so short queries don't catch scattered letters. Return picks the best match, Esc clears; both give keyboard focus back. The editor wants keyboard focus itself and the header buttons don't, so the DAW's keys (Space) never land in a search box or click a tab.
- **HeadRush pages** (beta, same `modellers` profiles, brand "HeadRush", orange): Core, Prime, Flex Prime (user guides v5.1.0) and Pedalboard, Gigboard (v2.1.2), MX5 (v1.5). Presets = each rig's MIDI PROG (Core/Prime/Flex shown 1-128, older shown 0-127 = PC 0-127; `Scheme::headrush` / `headrushOld`, label "Prog N"); no bank select or setlists. Scenes: one CC each from CC#21 (`scenePerCc`; Core 10, Prime 8, Flex 6, older none → page shows blocks only). Blocks 1-14 (older 1-11) CC#75+ are toggles (any value). Tuner CC#92 (not on older units), tap 64, rig 16/17, modes 94/97, looper 65-74 (+91 screen). Expression: Core CC#1 external; Prime / Flex CC#1 built-in, CC#2 external. Footswitch CCs (49+ / 50+): Core / Prime / Flex Prime have `Control::press` tiles (127 then 0); the older guides don't give values, so Pedalboard / Gigboard / MX5 have none. No MIDI over USB from a computer in the manuals (`Profile::usbMidi = false`, `AmpInfo::usbMidi`: wiring guide shows MIDI cables only); Flex Prime and MX5 have TRS MIDI (`midiIn`).
- **Nano Cortex page** (`neural.nano-cortex`, brand "Neural DSP", listed under the Neural DSP header; User Manual 2.2.0; **not beta**, `Profile::beta` false, like the QC Mini: no beta label, and the page line says only "Not tested on hardware"): presets PC 0-63 (`Scheme::nano`, "PC n"), slots Gate/Capture/Cab/FX1-5 CC#34-41 on/off, tuner CC#43, tap CC#42, expression CC#1; no scenes or looper (the Looper view is disabled, `viewFor`). TRS MIDI Type A in the shared EXP/MIDI jack (input mode MIDI) or USB; **no MIDI Out** (`Profile/AmpInfo::hasThru` false, `canChain()`: no daisy chain).
- **Darkglass Anagram page** (`darkglass.anagram`, KosmOS 1.17 manual): 01A-42C (hxStomp shape) with `pcOffset` 1 (it ignores value 0; 01A = PC 1, unconfirmed on hardware), scenes A-C = CC#107 1-3 (`sceneValueBase` 1, `sceneLetters`; the manual's table says 1-126, unconfirmed), Stomp footswitch bindings CC#17-19 (Value toggle logic), tuner CC#86, modes CC#85 1-3, next/prev CC#105-109, looper CC#110-118 (no clear), expression CC#89 + knob bindings CC#20-25. Darkglass ADAM / Alpha·Omega Photon have MIDI (TRS Type B) but no published chart; the Infinity 500 Combo and Exponent 500 amps are **pages** from their manuals' default mapping (`Scheme::darkglassAmp`: presets 1-5 = PC 2-6 via `pcOffset` 2; Bypass PC 0 / Mute PC 1 utilities; Per-value switches via `Control::value/offValue`: effects 0 = on, 1 = off, FX loop 1 = on; Combo's second view is "IR slots" (`looperTitle`); `Profile::cc0IsControl` / `Cue::cc0IsControl` pad with CC#32 = 0, never CC#0; no MIDI Out; Test sends `testMessage` PC 2); custom devices' Expression CC list includes CC#0; Microtubes Infinity is a template from openmidi's community chart (`Template::source`, TRS Type B, CC#0 = Compression so `padRepeat` / `state::usesCc0AsControl` stops the CC#0 = 0 padding).
- **Fractal / Line 6 pages** (`Source/Modellers.*` profiles, `Source/ModellerPage.cpp`, beta): `ampUnit` 4 (`state::modellerAmpUnit`) shows the model in `modellerProfile`; each model's data is a `Modellers > Modeller { profile } > ModPreset { setlist, presetIndex } > Scene` subtree plus `ModSwitch` names (`state::modeller`), kept in projects and the setup. 11 models with defined numbers: Helix Floor / LT / Rack, HX Stomp, HX Stomp XL, HX Effects, POD Go, Helix Stadium, Axe-Fx II, AX8, FX8. Presets store numbers (setlist = CC#32 value or -1, index), labels come from the scheme (01A, 33A on Stadium, A000, 17:1, A1). Load preset first: Line 6 snapshots on the same tick (buffered, documented), Fractal scenes/blocks 1/16 later; Line 6 footswitches never load first. "Switch to the preset's setlist" (`mdSendSetlist`) off by default, with the reminder button. The wiring guide and How to connect use the profile's connection facts (`hasDin`, `usbToThru`: POD Go USB only; Stadium passes USB to Thru with MIDI Over USB C; Axe-Fx II only with USB Adapter Mode; others undocumented). The page shows "From the <brand> manual, not tested on hardware" and About this unit (profile notes).
- **Device templates** (`Source/DeviceTemplates.*`, beta; labelled "template" in the device list, the docs say "any device with its own MIDI mapping works through templates or your own device"): the Axe-Fx III, FM9, FM3, VP4 and **Boss GT-1000 / GT-1000CORE** (`boss.gt-1000`: Program Changes follow its PROGRAM MAP, MAP SELECT = PROG; CCs only via an ASSIGN with SOURCE CC#1-31 / 64-95; preset tiles "BANK1 PC#n" = `bank 0, CC 32=0, PC n` with `programBase` 1; Switch 1-4 = CC#80-83 127/0 with MODE MOMENT; `expCc` 11; from the GT-1000 MIDI Implementation 1.20 and the GT-1000CORE Parameter Guide). Templates carry `programBase` and `expCc`. The Fractal ones have **no default CCs** (you assign them on the unit), so they're editable custom devices rather than pages; their notes start with that reason. Picking one creates a custom device (`templates::createUnit`, short tab name, `templateId`); picking it again selects the existing one. Preset tiles: CC#0 bank + PC (VP4: PC only); scene, tuner and looper tiles suggest the Axe-Fx II defaults (34, 15, 28-32) and say "assign it". FM3: not over USB MIDI. The device card shows `templates::disclaimer` in amber and an About this unit link with the template's notes (read-only, from the app, so updates reach existing devices); the device's own `notes` start empty ("Your notes"). Line 6 facts (setlists = CC#32, CC#54 = FS7, no FS6/FS12 CC, CC#68/64 act on any value, CC#69 after a PC is buffered, HX Stomp = 3 snapshots, POD Go USB only, Stadium's different map and second channel) live in the page profiles (`Modellers.cpp`).
- **Unit picker** (`Source/UnitPicker.cpp`, `ui::showUnitPicker`): the ▾ on the first tab opens the searchable list (built-ins, templates by brand, your devices, new / import). Search covers model, brand and aliases. It takes the keyboard while open and gives it back to the window after a pick.
- **Wiring guide** (`WiringGuide`, `makeWiringGuide (AmpInfo, view)`): three views, One device / Daisy chain / Separate outputs, opening on the wiring picked in How to connect. The first device is the unit on the first tab; the second is a generic "Second device, e.g. a Whammy". Don't make diagrams or docs assume QC + Whammy: the Whammy is the worked example.
- **Header tabs are radio buttons:** switching tabs also fires `onClick` on the tab being switched off, so the first tab's handler only reacts when its own toggle is on (otherwise clicking the other tab opened the device list).
- Default channels: QC 1 (never Omni), Whammy 2. Clips keep the channel they were dragged with, so until the user clicks **Done** in a page's MIDI strip (per-computer flag `ui::channelsConfirmedFlag`), the strip shows the reminder in amber. DocShots sets the flag for its shots and restores it. Don't state the Whammy V channel-setting procedure from memory; point to its manual.
- Quad Cortex page has a **Scenes & Stomps | Expression** switch (`qcExpressionView`). Expression (`Source/QcExpression.cpp`) sends CC#1 / CC#2 (QC expression pedal 1/2; no physical pedal needed): Exp 1/2 switch, "Set to" tiles, shapes and Draw. Moves cards for the Whammy treadle and QC expression share `Source/MovesPanel.*` (configured by `MovesConfig`), and the CC curves share `ccMove` in CueModel.cpp. Expression assignments live in each QC preset; the "assign" steps on the QC aren't verified, so keep them generic. Expression clips act on the loaded preset unless the opt-in **Load 1A first** (`expLoadFirst`, `qc::withPresetFirst`) is on.
- **Draw > Wave...** (`MovesPanel::WaveEditor`, `cues::whammy::waveDrawing`): Sine / Triangle / Square / Saw up / Saw down, waves ½-8, phase, shape (asymmetry / pulse width), low / high, grow (amp skew) and speed (frequency skew), like Reaper's CC LFO; writes into the pad (replaces it), in every MovesPanel. Drawings are 128 points since v0.8.5 (`drawPoints`); older 64-point ones are resampled on load, and "edited" compares at the current resolution.
- **My drawings** (`state::myDrawings()`, `drawings.xml` next to the default setup): saved drawn moves shared by both Draw modes, every project and instance. Never stored in projects (sanitise strips it) or in the default setup; Export setup includes it and Import merges it (never removes). Call `state::storeMyDrawings()` after every change. Tests and DocShots must use `state::useMyDrawingsFile` / a local list so the user's own file is never touched. `sweepDrawingName` / `expDrawingName` name the drawing loaded on each pad.
- Scene and stomp tiles "Load 1A first" by default (preset PC, then the scene or footswitch 1/16 later; Expression's Load 1A first uses the same gap). A setting to shorten the gap was tried and dropped: it only helps when the preset is already loaded, where "Load 1A first off" or dropping the tile 1/16 early already work, and risks the QC missing the scene after a real preset change; with that switch off (`comboPresetScene`) they act on the current QC preset. Scenes and Expression each have one "Load 1A first" toggle, worded the same way.
- **MIDI files** (`writeMidiFile`, `lengthPadding`): a cue whose events all sit on tick 0 gets a message 1/16 later, because Ableton Live refuses clips with no length. Never a second Program Change (Fractal reloads on a redundant PC by default): a clip ending in a PC repeats its last bank/setlist CC, or sends CC#0 = 0 if it has none. Cues marked `Cue::toggles` (QC Tap, Line 6 footswitch presses, HeadRush block toggles, every modeller utility/looper action) get CC#0 = 0 instead of a repeat, which would undo them (v0.7.0 sent them twice). Padding must stay harmless.
- Standalone app (`Source/StandaloneApp.cpp`, custom JUCE standalone): no audio inputs, no Audio/MIDI settings window. Tiles go straight to the MIDI port picked in How to connect or Options > MIDI Output (`PedalCuesProcessor::setDirectMidiOutput`, saved as `standaloneMidiOutput` in settings.xml). Menus: macOS app menu (About, Check for Updates, auto-check toggle), File (setup), Options (MIDI Output), Help (incl. Wiring Guide). The tempo is set by the user (`setManualBpm`, `standaloneBpm`).
- **Tabs "Amps & Modellers" / "Effects & Pedals"**. The second tab (`makePedalPage`, `pedalInfo`): the Whammy V / DT (`fxUnit` 0), a custom MIDI device (`fxUnit` 1, `fxCustomUnit`), No pedal (`fxNone` 2, `NoPedalPage`) or a pedal page (`fxModeller` 3, `fxProfile`, a `modellers::Profile` with `pedal = true`; `makeModellerPage (p, true)` with its own `fxView` / `fxPedal` / `fx*` moves ids and its channel `IDs::channel` on the Modeller node, default 3, `state::fxModellerChannel`). Picked with its own ▾ (`showPedalMenu`, `showUnitPicker (..., pedalsTab)`: No pedal, DigiTech Whammy, pedal pages and pedal templates (`Template::pedal`: VP4, Microtubes Infinity) by brand, then devices with `category` "pedal", never the one on the first tab). The amp list skips pedal profiles/templates and sanitise rejects them on the first tab. Custom devices carry `IDs::category` ("amp"/"pedal"); the device "..." menu moves them between tabs. ## Quad Cortex USB sync (`Source/QcUsb.*`, `Source/QcSyncDialog.cpp`)

- Client for the QC's private USB-HID protocol (VID 0x152A, PID 0x880A QC / 0x892F Mini, interface 5, 129-byte reports), via hidapi (FetchContent). Follows pyquadcortex's `docs/protocol.md` (MIT).
- `readSetlists` sends only READs, the handshake, Connection and KeepAlive (incl. `RecallPreset{READ}` + `SetlistPosition{READ}` for the loaded preset's scenes/stomps). The opt-in `scanPresets` additionally sends `SetlistPosition{UPDATE}` (recall) and `Scene{UPDATE}` (restore the scene), refuses when `PresetDirty` is true, and restores the original preset. **Never send anything else that writes: no `RecallPreset` UPDATE/SAVE (can hang the unit), no `File` without an explicit READ action (an action-less File is a save), no Grid/SceneLabel/SceneColor/Tuner/power writes.**
- Flow: Version READ → ResetCommsBuffers → Version UPDATE (cortex_control_version = the unit's CorOS) → Connection true → 12 READs (ModelRepo first) → File READ type 0 → collect one File push per folder → Connection false. KeepAlive `08 01 18 01` every 1 s. Write return values are always errors: ignore them.
- Setlists = keys under `/media/p4/Presets/` plus `/opt/neuraldsp/Factory Library`. **The QC doesn't report setlist numbers** (no order field is known): the sync dialog guesses (My Presets, then A-Z), says so in amber, and remembers the numbers the user picks per folder key (`qcSetlistNumbers` setting). Its "Send the setlist with every preset change" switch (on by default) sets `sendSetlist`. The QC page shows "Setlists not sent: turn on" when presets span several setlists with `sendSetlist` off. To find the QC's real order, run `PedalCuesTests --qc-setlists` with the QC on USB: it prints setlists in arrival order with undecoded folder fields (`Folder::arrival`, `otherFields`). Slot = ProductData.index (or array position), bank = pos/8+1, slot letter = pos%8.
- Unit tests decode real captures in `Tests/fixtures/*.hex` (from pyquadcortex, MIT). Hardware testing needs the user's QC (quit Cortex Control first).
